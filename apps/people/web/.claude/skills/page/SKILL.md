# Page

Routes live in `src/app/`. They hold only routing concerns; markup and data wiring live in a
view under `src/domains/<domain>/views/`. See the `component` skill for the view anatomy.

Before using an unfamiliar Next API, read its doc in `node_modules/next/dist/docs/01-app/`.
`01-getting-started/03-layouts-and-pages.md` and `08-caching.md` cover this skill's ground.

## Canonical page

```tsx
import { UserProfileView } from "@domains/user/views";

export default function UserPage({ params }: PageProps<"/users/[id]">) {
  return <UserProfileView userId={params.then(({ id }) => id)} />;
}
```

- **Type props with the global `PageProps<"/route">`** (and `LayoutProps<"/route">`). The
  types are generated by `next dev` / `next build` / `next typegen`, so `npm run typecheck`
  runs typegen first.
- **`params` is a Promise. Don't `await` it in the page.** Awaiting at the top makes the whole
  route block on request data. Pass the promise (mapped to what the view needs) into the view,
  and await it inside a component that sits under `<Suspense>`. The view's static shell then
  prerenders and only the data part streams. `next build` should show the route as
  `◐ (Partial Prerender)`.
- The page itself stays sync. It has no `async`, no fetching and no JSX beyond the view.

## Suspense under Cache Components

`cacheComponents` is on. Any uncached async work, and any runtime API (`params`,
`searchParams`, `cookies()`, `headers()`), must be either:

1. inside a `<Suspense fallback={<XSkeleton />}>` boundary (streams per request), or
2. cached with `'use cache'` + `cacheLife(...)` (joins the static shell).

Otherwise the dev overlay shows a **blocking-route** error. Put Suspense boundaries in the
view, around the smallest part that needs the data, and keep layout chrome outside them.
Choosing between 1 and 2 is covered in the `data-fetching` skill.

## not-found

- `app/<route>/not-found.tsx` renders a view too: `return <UserNotFoundView />`.
- Trigger it from the data component with `notFound()` from `next/navigation` when the API
  returns `null` for the entity (e.g. `user(id)` → `null`). A thrown network/server error is
  not a 404; let it reach `error.tsx`.

## Metadata

Static: `export const metadata: Metadata = { title: "…" }`. Data-driven: `export async function
generateMetadata({ params }: PageProps<"/users/[id]">)`, reusing the same cached data function
the view uses so the query isn't duplicated (see `data-fetching`).

## Checklist

1. Create the view (+ skeleton) in `domains/<domain>/views/<Name>View/`, barrel it.
2. Add `app/<route>/page.tsx` in the canonical shape.
3. Add `not-found.tsx` if the route has an entity param.
4. `npm run format && npm run lint && npm run typecheck`, then `npm run build` and confirm the
   route is `◐` (or `○` if fully static), not `ƒ`.
